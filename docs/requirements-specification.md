## 1. 文書の目的

本書は、PDF2Excel システムの目的、対象範囲、利用者価値、機能要件、非機能要件、運用条件を明確にし、利用者、運用担当者、保守担当者の認識をそろえるための要件定義書です。  
本書は「何を実現するべきか」を定義する文書であり、詳細な実装方法は [technical-description.md](technical-description.md) に記載します。

## 2. 背景

業務上、表形式のテキスト PDF を Excel へ転記したい需要があります。  
対象 PDF は同一または近い帳票レイアウトで、1 件あたりおおむね `100 行 x 30 列` 程度、件数は `50 件前後` を想定しています。  
手作業で PDF を開いてコピー・貼り付けすると、次の問題があります。

- 作業時間が長い
- 空白セルを含む表で列ずれしやすい
- 作業者ごとに手順がぶれる
- 失敗や抜け漏れの追跡がしにくい

これを解決するため、Windows と Excel(M365) を前提に、追加インストールなしで使える一括変換システムを用意することが目的です。

## 3. システム概要

PDF2Excel は、複数のテキスト PDF を一括で読み込み、表データを 1 つの Excel ブックへ集約するローカル実行型システムです。  
主な特徴は次の通りです。

- `BAT + PowerShell + Excel(M365)` のみで動作する
- テキスト PDF を対象とし、OCR は使わない
- `A 列 = ファイル名`、`B 列以降 = 表データ` の形式で出力する
- `Summary`、`Result`、`Errors`、`Control` を基本にし、V2 では `Review` を含めて結果を可視化する
- 帳票プロファイルにより、想定列数やヘッダー除外行数を切り替えられる
- 実行前チェックにより、誤実行を減らす
- 環境チェック、実行履歴、設定ウィザードで運用性を補強する

## 5. 用語定義

- テキスト PDF
  - 文字をマウスで選択できる PDF
- 画像 PDF
  - スキャン画像主体で、文字選択できない PDF
- 帳票プロファイル
  - 帳票ごとの抽出条件を定義する JSON 設定
- staging
  - 実行時に対象 PDF を一時配置する処理領域
- Result
  - 正常に抽出できた明細データ
- Errors
  - PDF 単位の失敗情報
- Summary
  - 実行全体の集計情報と PDF 単位のサマリー情報

## 6. システム化の目的

### 6.1 業務目的

- PDF から Excel への転記作業を短時間で行えるようにする
- 同じ帳票群の処理を誰でも同じ手順で再現できるようにする
- 変換結果と失敗理由を分けて確認できるようにする

### 6.2 品質目的

- 列ずれの原因追跡をしやすくする
- 誤った入力フォルダや出力先の選択を減らす
- 保守時に帳票条件を設定で切り替えやすくする

## 7. 対象範囲

### 7.1 対象とする範囲

- Windows 上でのローカル実行
- Excel(M365) デスクトップ版を利用した変換
- 複数テキスト PDF の一括変換
- 既定プロファイルおよび任意プロファイルでの帳票条件切替
- 実行前チェック、実行結果サマリー、エラー分類の表示
- 配布用最小パッケージの作成

### 7.2 対象外

- OCR による画像 PDF 変換
- Web システム化
- サーバー常駐実行
- PDF の内容編集
- Excel 以外への高度な変換ルール設計 UI
- 帳票ごとの自動学習

## 8. 想定利用シナリオ

### 8.1 日常運用

1. 利用者が `run_pdf2excel.bat` を起動する
2. PDF ファイルまたは PDF フォルダを選択する
3. 保存先を指定する
4. 実行前チェックを確認して続行する
5. 出力された Excel の `Summary`、`Result`、`Errors` を確認する

### 8.2 帳票差分対応

1. 保守担当者が既定プロファイルをコピーする
2. 想定列数、ヘッダー除外行数などを調整する
3. 少量の実 PDF で確認する
4. 利用者へ新しいプロファイルを配布する

### 8.3 障害対応

1. `Control` シートで状態、件数、ログファイルを確認する
2. `Errors` シートで `ErrorCode` と `ErrorCategory` を確認する
3. 必要に応じて `logs` フォルダの最新ログを見る

### 8.4 他者配布

1. 配布担当者が最小配布パッケージを作成する
2. 受領者に zip または最小配布フォルダを渡す
3. 受領者は同梱マニュアルに従って初回実行する
4. 受領者は少数の PDF で動作確認した後、本番運用へ入る

## 8.5 利用者ストーリー

- 利用者として、複数の PDF をまとめて選び、1 回で Excel 化したい
- 利用者として、誤ったフォルダや保存先を選んだ場合に実行前に気づきたい
- 利用者として、失敗した PDF だけを一覧で確認したい
- 運用担当として、問い合わせ時に原因をエラー分類とログから素早く特定したい
- 保守担当として、帳票差分をコード修正ではなく設定変更で吸収したい

## 9. 機能要件

### FR-01 起動機能

- 利用者は `run_pdf2excel.bat` からシステムを起動できること
- 対話メニューからファイル選択実行、フォルダ選択実行、マニュアル参照、出力フォルダ参照、プロファイルフォルダ参照ができること
- 引数付きの非対話実行も可能であること

### FR-02 入力選択機能

- 利用者は次のいずれかで入力対象を指定できること
- PDF ファイル複数選択
- PDF フォルダ指定
- PowerShell 引数によるファイル指定
- PowerShell 引数によるフォルダ指定

### FR-03 入力検証機能

- 指定された入力が存在することを確認すること
- PDF 以外のファイルが指定された場合はエラーにすること
- 同名 PDF が複数存在する場合は明示的に停止すること

### FR-04 実行前チェック機能

- 実行前に次の情報を表示すること
- 対象 PDF 数
- 出力ファイル
- 上書き有無
- 使用プロファイル
- 想定列数
- ヘッダー除外行数
- 想定行数
- 代表ファイル名
- 対話実行時は、利用者が続行可否を選べること
- 自動実行時は `-NoConfirm` により確認入力を省略できること

### FR-05 帳票プロファイル読込機能

- システムは JSON 形式の帳票プロファイルを読み込めること
- 既定プロファイル `default.json` を持つこと
- `-ProfileName` および `-ProfilePath` で切り替え可能であること

### FR-06 帳票プロファイル適用機能

- システムは次のプロファイル項目を抽出処理に反映できること
- 想定列数
- ヘッダー除外行数
- 想定行数
- 想定列数超過の許可有無
- 優先する表種別
- 優先する表名文字列
- 優先する表 ID 文字列
- 出力列プレフィックス

### FR-07 PDF staging 機能

- 実行対象 PDF を一時 staging フォルダへ配置すること
- 不要な残留 PDF を除去できること
- `input` フォルダ自己参照時でも自己削除しないこと

### FR-08 PDF 表抽出機能

- テキスト PDF から表候補を取得できること
- 複数候補の中から、プロファイル条件に最も近い表を選べること
- 指定ヘッダー行数を除外できること
- 想定列数まで不足列を空文字で補完できること
- 出力データにファイル名列を付与できること

### FR-09 結果出力機能

- 正常データを Excel ブックへ出力できること
- 出力ブックには少なくとも次のシートを含むこと
- `Control`
- `Summary`
- `Result`
- `Errors`

### FR-10 Result シート要件

- `Result` シートには成功データのみを出力すること
- A 列には元 PDF ファイル名を出力すること
- B 列以降には帳票データ列を出力すること
- 列数は使用プロファイルに従うこと

### FR-11 Summary シート要件

- `Summary` シートには次を表示すること
- 対象 PDF 数
- 成功 PDF 数
- 失敗 PDF 数
- 取込データ行数
- エラー件数
- 処理時間
- 使用プロファイル
- 出力ファイル
- PDF ごとの成功 / 失敗および取込件数
- エラー分類別件数

### FR-12 Errors シート要件

- `Errors` シートには失敗した PDF を 1 行 1 件で出力すること
- 次の情報を保持すること
- ファイル名
- エラーコード
- エラー分類
- 利用者向けメッセージ
- 技術詳細
- 候補表の列数
- 候補表の行数
- 候補表 ID
- 候補表種別
- 候補表名

### FR-13 Control シート要件

- `Control` シートには実行管理情報を表示すること
- 入力フォルダ
- 出力ファイル
- ログファイル
- 最終実行日時
- 状態
- 対象 PDF 数
- 取込データ行数
- エラー件数
- 成功 PDF 数
- 失敗 PDF 数
- 処理時間
- 使用プロファイル
- プロファイル説明

### FR-14 ログ出力機能

- 実行ログを `logs` フォルダへ出力すること
- ログにはタイムスタンプ、レベル、メッセージを含むこと
- 情報、警告、エラーを識別できること

### FR-15 テンプレート生成機能

- Excel テンプレートを PowerShell スクリプトで再生成できること
- テンプレートには `Control`、`Summary`、`Result`、`Errors` シートが揃うこと
- VBA モジュールを取り込めること

### FR-16 配布パッケージ生成機能

- 他者配布用の最小構成フォルダを生成できること
- zip 形式の配布物も生成できること
- 配布物に専用マニュアルを含めること

### FR-17 実行結果継続性要件

- 一部 PDF の失敗時に、正常 PDF の変換を継続できること
- PDF 単位失敗と実行全体失敗を区別できること

### FR-18 再実行容易性要件

- 同じ入力条件で再実行可能であること
- 出力、ログ、使用プロファイルを後から追跡できること

### FR-19 配布先利用性要件

- 配布先が開発用ファイルなしでも利用できること
- 配布先に最低限必要なマニュアルを同梱できること

## 9.1 業務ルール

- 1 回の実行単位では、可能な限り同一または近い帳票レイアウトの PDF をまとめる
- 同名 PDF は同時処理しない
- 実運用では、まず少数件で確認してから大量件数へ広げる
- `Errors` シートに出た PDF は、元 PDF とプロファイルの両面から確認する
- `Result` シートの内容を最終業務データとして使う前に、利用者が妥当性確認を行う

## 9.2 データ要件

### 入力データ要件

- ファイル形式は `.pdf`
- 文字選択可能なテキスト PDF であること
- 表が `Pdf.Tables` で認識可能であること
- 1 運用単位で同一系統の帳票であること

### 出力データ要件

- 出力形式は `.xlsx`
- `Result` は表形式で後続加工しやすいこと
- `Errors` は失敗 1 件につき 1 行であること
- `Summary` は件数集計の一次確認に使えること

### データ保持要件

- ログは実行単位で分かれること
- 出力ブック内に最低限の実行メタ情報を保持すること
- 一時ファイルは不要に残さないこと

## 10. 非機能要件

### NFR-01 実行環境

- Windows 環境で動作すること
- Excel(M365) デスクトップ版が利用可能であること
- PowerShell から実行できること

### NFR-02 追加インストール制約

- 原則として追加インストール不要であること
- 標準構成は `BAT + PowerShell + Excel(M365)` のみで動作すること

### NFR-03 操作性

- 利用者は BAT メニュー中心で操作できること
- コマンドライン知識がなくても使えること
- 実行前チェックと Summary で全体状況が把握できること

### NFR-04 可観測性

- 実行状況をログで追えること
- 失敗理由が利用者向けと保守向けの両方で読めること
- 成功件数、失敗件数、処理時間を把握できること

### NFR-05 保守性

- 抽出条件をコード変更ではなくプロファイル設定で切り替えられること
- テンプレート再生成をスクリプト化していること
- 統合テストにより主要シナリオを再確認できること

### NFR-06 信頼性

- 1 件の壊れた PDF により全件停止しないこと
- 壊れた PDF は Errors へ退避し、他件の処理継続を優先すること
- Excel プロセスと runtime 一時ファイルが不要に残らないこと

### NFR-07 性能

- 50 件前後の PDF を現実的な待ち時間で処理できること
- 少なくとも業務上の手作業より短時間で完了すること
- 詳細な秒数要件は環境差が大きいため固定しないが、実行時間を記録できること

### NFR-08 データ整合性

- ファイル名列が正しく保持されること
- 空白セルは空文字として扱えること
- 想定列数より不足する列は空欄補完できること

### NFR-09 セキュリティ

- ネットワーク接続を前提にしないこと
- ローカルファイルのみを扱うこと
- ログに最低限必要な情報のみ出力すること

### NFR-10 互換性

- PowerShell から実行可能であること
- Excel(M365) の標準的な Power Query 機能で動作すること
- 利用者配布時に追加の Python や外部ライブラリを要求しないこと

### NFR-11 配布容易性

- 実行に必要な最小ファイル群を切り出せること
- zip 化して配布可能であること
- 配布先で手順書だけ見れば使い始められること

### NFR-12 テスト容易性

- 主要シナリオを PowerShell スクリプトで自動確認できること
- テストレポートを md と json の両形式で残せること

### NFR-13 運用復旧性

- 失敗時に再実行しやすいこと
- 一時ファイルや残留 Excel プロセスが復旧を妨げないこと

## 11. 制約条件

- OCR は実装しない
- 画像 PDF は対象外
- 抽出精度は Excel の `Pdf.Tables` に依存する
- 帳票差分が大きい場合はプロファイル分割または別運用が必要
- マクロ実行が無効な場合でも、PowerShell 側保存で結果出力を継続できること

## 12. 前提条件

- PDF がテキスト選択可能であること
- 同一運用単位では、帳票レイアウトが同一または近いこと
- Windows と Excel が利用可能であること
- 出力先フォルダへ書き込み権限があること

## 12.1 想定外入力

本システムでは次の入力は想定外とする。

- 画像 PDF
- パスワード保護 PDF
- 大幅に異なる帳票を混在させた一括投入
- 1 ファイル内に多数の異種表が混在し、主対象表を定義できない PDF

## 14. 受け入れ条件

本システムは、少なくとも次を満たしたとき受け入れ可能とする。

1. 利用者が BAT 起動で PDF 群を変換できる
2. 実行前チェックが表示される
3. 既定プロファイルで正常変換できる
4. カスタムプロファイルで列数変更を反映できる
5. Summary、Result、Errors、Control の 4 シートが出力される
6. 壊れた PDF 混在時も他 PDF の変換が継続する
7. エラー分類が Errors に記録される
8. 主要シナリオの統合テストが成功する

## 14.1 受け入れ判定観点

- 機能観点
  - 必要なシートが出力されるか
  - 件数が Control / Summary / Result / Errors で整合するか
- 操作観点
  - BAT 起動だけで利用者が実行できるか
  - 実行前チェックで誤入力に気づけるか
- 運用観点
  - 失敗理由を Errors とログで切り分けられるか
  - 再実行が容易か
- 保守観点
  - プロファイル差し替えで帳票条件を変更できるか
  - テストと配布が再現可能か

## 15. 既知の限界

- 画像 PDF は対象外
- 列境界の曖昧な PDF は列ずれの可能性がある
- Power Query の PDF 解釈結果は帳票品質に依存する
- 高度な帳票差分吸収はプロファイルだけでは限界がある

## 15.1 リスク

- Power Query の PDF 解釈が Office 更新で変化する可能性がある
- 帳票差分が蓄積すると、プロファイル運用だけでは複雑になる可能性がある
- 業務利用者が `Errors` を見ずに `Result` だけで判断すると、失敗 PDF を見落とす可能性がある
- マクロ無効環境ではフォールバック動作に依存するため、一部の Excel 表示挙動が変わる可能性がある

## 15.2 運用上の補足

- 本システムは「完全自動判定」ではなく「一次変換と確認支援」のシステムである
- 業務確定値として使う前に、利用者によるサンプリング確認を推奨する
- 新しい帳票を追加する場合は、まず別プロファイルとして切り出す運用を推奨する
