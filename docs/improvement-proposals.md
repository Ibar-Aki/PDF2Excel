# PDF2Excel 改善提案レポート

- 作成日: 2026-03-13 00:58 JST
- 作成者: Codex (GPT-5)
- 更新日: 2026-03-14

## 目的

このレポートは、現在の PDF2Excel をより便利に、より使いやすく、より汎用的にするための改善案を整理したものです。  
単なる機能追加案ではなく、実運用で効くかどうか、保守しやすいかどうか、今の構成に無理なく載せられるかどうかを重視してまとめています。

## 現状の強み

- 追加インストールなしで `BAT + PowerShell + Excel(M365)` だけで動く
- 利用者向け入口が `run_pdf2excel.bat` にまとまっている
- Power Query の `Pdf.Tables` を使っており、テキスト PDF には比較的強い
- `Result` と `Errors` を分けており、失敗ファイルを追える
- テストと運用ドキュメントが一通り整っている

## 現状の制約

- 抽出精度が `Pdf.Tables` に強く依存し、帳票差分に弱い
- 利用者が「どの設定で実行したか」を後から追いにくい
- 実行前に列ずれを確認するプレビュー機能がない
- PDF レイアウトごとのルールを積み増す仕組みがまだ弱い
- Excel 依存のため、バッチ処理の見通しや失敗理由がやや分かりにくい

## 総評

このシステムは、同一帳票をまとめて変換する用途には十分に実用的です。  
一方で、今後「担当者が増える」「帳票種類が増える」「再実行や障害対応が増える」状況になると、設定の見える化、事前確認、帳票プロファイル化、運用ログの整理がボトルネックになります。  
つまり、次の改善の軸は以下の 3 つです。

1. 誰でも迷わず使えること
2. 失敗しても原因がすぐ分かること
3. 帳票差分に対応しやすいこと

## 詳細提案

### 1. 実行前チェック画面

実装状況: 実装済み

#### 提案内容

変換開始前に、次の情報を一覧表示する確認ステップを追加します。

- 対象 PDF 件数
- 選択された入力元
- 保存先ファイル名
- 使用するテンプレート
- 想定列数
- 上書きの有無
- 代表ファイル名の先頭数件

#### 期待効果

- 別フォルダを誤って選ぶ事故を減らせます。
- 出力先の上書きミスを減らせます。
- 利用者が「今から何が起きるか」を理解しやすくなります。

#### 実装案

- BAT メニューの最後に「実行確認」表示を追加する
- PowerShell 側で `-WhatWillRun` 相当の表示関数を作る
- `Y/N` で最終確認してから Excel を起動する

### 2. 帳票プロファイル機能

実装状況: 実装済み

#### 提案内容

帳票ごとの抽出ルールを JSON または CSV で持てるようにします。  
例えば、次のような項目をプロファイル化します。

- 帳票名
- 想定列数
- ヘッダー除外行数
- 優先採用する表番号
- 列名一覧
- 空行判定ルール
- 特定列のトリムや置換ルール

#### 期待効果

- 帳票が 1 種類から複数種類に増えても同じ仕組みで運用できます。
- 個別の帳票差分をコード改修ではなく設定で吸収しやすくなります。
- 将来的なメンテナンスコストが大きく下がります。

#### 実装案

- `config/profiles/*.json` を追加する
- `Control` シートまたは PowerShell 引数でプロファイル名を選べるようにする
- プロファイル未指定時は `default` を使う

### 3. 実行結果サマリーの強化

実装状況: 実装済み

#### 提案内容

完了後に、現状の件数表示に加えて、以下をまとめて出します。

- 成功 PDF 件数
- 失敗 PDF 件数
- 総出力行数
- PDF ごとの出力行数
- 処理時間
- エラー理由別件数

#### 期待効果

- 利用者が Excel を開く前に結果の良し悪しを判断できます。
- 大量処理時に「何件落ちたか」「どれが怪しいか」がすぐ分かります。

#### 実装案

- `Control` シートに実行結果欄を追加する
- PowerShell コンソールにも同内容を表示する
- `output` に `run-summary_yyyyMMdd_HHmmss.csv` を出す

### 4. エラー分類の明確化

実装状況: 実装済み

#### 提案内容

今の `Errors` シートを、利用者に意味が通る分類へ整理します。  
最低でも以下に分けると運用しやすくなります。

- PDF が壊れている
- 表を検出できない
- 列数が想定と合わない
- Excel 起動失敗
- テンプレート不整合
- 保存先に書き込めない

#### 期待効果

- 問い合わせの一次切り分けが簡単になります。
- 「PDF の問題か、システムの問題か」を判断しやすくなります。

#### 実装案

- エラーコード列を追加する
- 利用者向けメッセージ列と技術メッセージ列を分ける
- `troubleshooting.md` とエラーコードを対応させる

### 5. 出力列マッピング設定

#### 提案内容

現状は `A列=ファイル名、B-AE列=抽出列` で固定ですが、将来的には以下を設定可能にすると便利です。

- 列名の付与
- 不要列の除外
- 列順の入れ替え
- 固定値列の追加
- ファイル名から拡張子を除いた値の出力

#### 期待効果

- 実務でそのまま使える形に近づきます。
- 後工程の Excel 加工を減らせます。

#### 実装案

- `config/column-map.csv` を追加する
- 1列目の論理名、出力順、変換ルールを定義する
- Power Query または PowerShell 後処理で整形する

### 6. サンプル実行モード

#### 提案内容

初心者向けに、`samples/pdf/` を使ったお試し実行メニューを追加します。

#### 期待効果

- 利用者が本番前に動作イメージを掴めます。
- Excel やマクロ設定の問題を先に見つけやすくなります。

#### 実装案

- BAT メニューに `サンプルで試す` を追加する
- 完了後にマニュアルの該当章を開く

### 7. 実行履歴台帳の保存

#### 提案内容

各実行の情報を 1 行で残す履歴ファイルを用意します。  
保存候補は `reports/run-history.csv` です。

#### 保存項目案

- 実施日時
- 実行者 PC 名
- 入力元
- 対象 PDF 件数
- 成功件数
- 失敗件数
- 出力行数
- 出力ファイル
- 処理時間
- 使用テンプレート版

#### 期待効果

- いつ何を処理したか後から追えます。
- 障害発生時に再現条件を特定しやすくなります。

### 8. テンプレート診断モード

#### 提案内容

Excel、マクロ、Power Query、保存権限などの前提条件をまとめてチェックする診断モードを追加します。

#### 期待効果

- 初回セットアップ時の詰まりどころを潰せます。
- 「なぜ動かないのか」が見えやすくなります。

#### 実装案

- BAT メニューに `環境チェック` を追加する
- 確認内容を一覧表示する
- 結果を `reports/environment-check.md` に保存する

### 9. 複数出力形式対応

#### 提案内容

現在は `xlsx` のみですが、現場で扱いやすいように次も検討できます。

- `csv`
- `xlsx + errors.csv`
- PDF ごとに別シート出力
- PDF ごとに別ファイル出力

#### 期待効果

- 後工程システムへの取り込みがしやすくなります。
- 部門ごとの運用差に対応しやすくなります。

### 10. GUI ランチャー化

#### 提案内容

BAT メニューをさらに進めて、PowerShell WinForms もしくは簡易 WPF で小さな操作画面を作ります。

#### 期待効果

- 非 IT 利用者でも操作しやすくなります。
- 入力、保存先、実行結果、エラー要約を 1 画面にまとめられます。

#### 補足

これは有効ですが、現時点では最優先ではありません。  
先に確認画面、プロファイル、履歴台帳のほうが費用対効果は高いです。

### 11. OCR 連携の準備

#### 提案内容

今回はテキスト PDF 前提ですが、将来的に画像 PDF へ広げるなら、今のうちに設計上の拡張ポイントを分けておくべきです。

#### 推奨方針

- 抽出エンジンを `Pdf.Tables` 固定ではなく抽象化する
- 将来の候補として OCR ルートを別系統で定義しておく
- ただし v1 では実装しない

## おすすめ実施順

すぐ効く改善です。費用対効果が高く、現場導入しやすい内容です。

- 実行前チェック画面
- 実行結果サマリー強化
- エラー分類の明確化
- サンプル実行モード

### 第2段階

汎用性と保守性を大きく上げる改善です。

- 帳票プロファイル機能
- 出力列マッピング設定
- 実行履歴台帳
- テンプレート診断モード

### 第3段階

将来拡張として価値がありますが、先に第1段階と第2段階を固めるほうが合理的です。

- GUI ランチャー化
- 複数出力形式対応の本格化
- OCR 連携準備

## 改善後の理想像

理想は、「利用者は PDF を選んで開始するだけ、運用担当は履歴とエラーコードで追える、保守担当は帳票差分を設定で増やせる」という状態です。  
今の PDF2Excel は土台としては良いので、次はコードを大きく作り直すより、設定化・見える化・確認機能の追加で伸ばすのが正攻法です。

## 結論

最も重要なのは、機能を増やすことそのものではなく、利用者が安心して実行できることと、帳票差分に対してコード改修なしで対応しやすくすることです。  
したがって、次に着手すべき改善は以下の 4 点です。

1. 実行前チェック画面
2. 帳票プロファイル機能
3. 実行結果サマリー強化
4. エラー分類の明確化

この 4 点を入れるだけで、使いやすさ、問い合わせ対応、汎用性の 3 つがかなり改善します。
