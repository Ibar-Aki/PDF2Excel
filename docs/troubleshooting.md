# PDF2Excel トラブルシューティング

- 作成日: 2026-03-13 00:51 JST
- 作成者: Codex (GPT-5)
- 更新日: 2026-03-20

## 目的

この資料は、PDF2Excel の実行時に起きやすい問題を、症状別に切り分けるための手引きです。

## まず最初に確認すること

1. まず BAT メニューの `[0] 環境チェック` を実行し、`reports/environment-check.md` を確認する
2. [Control シート](user-manual.md) の状態、件数、ログパスを確認する
3. `reports/run-history.csv` に直近実行が残っているか確認する
4. `%LOCALAPPDATA%\PDF2Excel\logs` または `logs` フォルダの最新ログを開く
5. 元PDFがテキスト選択可能か確認する
6. 他の PDF とレイアウト差が大きくないか確認する
7. 実行前チェックの入力元、保存先、プロファイルが正しいか確認する

## 症状別の対処

### 0. `RUN_LOCKED` と表示される

確認ポイント:

- すでに別の PDF2Excel 実行が動いていないか
- Excel や PowerShell が前回の実行後に残っていないか

よくある原因:

- 二重起動した
- 前回の実行がまだ終わっていない
- 前回の異常終了で `run.lock` だけが残った

対処:

- 先に動いている変換が終わるまで待つ
- 不要な Excel / PowerShell を閉じる
- その後に再実行する
- 環境チェックで `実行競合状態` が `前回異常終了の可能性` と出た場合は、そのまま再実行して自動回復するか確認する

補足:

- この停止は保護動作です
- 同時実行で staging や一時ファイルが壊れないように、1 実行だけ許可しています
- `run.lock` の詳細は環境チェックでも確認できます
- `run.lock` の内容が壊れていても、環境チェックでは `内容読取不可` として分けて表示されます

### 0-1. `LOCAL_RUNTIME_UNAVAILABLE` または `LOCALAPPDATA` 関連エラーが出る

確認ポイント:

- Windows の通常ユーザー環境で起動しているか
- `%LOCALAPPDATA%` が利用できるか
- 共有フォルダ上ではなくローカル展開先から実行しているか

対処:

- `run_pdf2excel.bat` 一式をローカルフォルダへ展開し直す
- エクスプローラーから通常起動する
- 環境チェックの `LOCALAPPDATA runtime/logs` 項目を確認する

### 1. 変換結果の Excel が作成されない

確認ポイント:

- Excel(M365) デスクトップ版が起動できるか
- 保存先フォルダに書き込み権限があるか
- `logs` に `処理に失敗しました` が出ていないか
- `reports/run-history.csv` の `Status` と `ErrorCode` が何になっているか

よくある原因:

- Excel COM 起動失敗
- 保存先の選択ミス
- 出力先ファイルを他のアプリがロックしている

対処:

- Excel を手動で一度起動して閉じる
- 別の保存先を選ぶ
- 同名の `xlsx` を閉じてから再実行する
- 環境チェックの `Excel COM` と `output 書き込み` を確認する

### 2. `Errors` シートに PDF が多く出る

確認ポイント:

- `ErrorCategory`
- `ErrorCode`
- `UserMessage`
- `CandidateColumns` と `CandidateRows`

よくある原因:

- レイアウト差が大きい
- 表認識が安定しない PDF
- プロファイルの想定列数が合っていない

対処:

- 似た帳票レイアウトごとに分けて実行する
- 実PDFを数件目視確認する
- `config\profiles` の `expectedColumns` を見直す
- 使うプロファイルが違う場合はメニューの `[9] プロファイルを選ぶ` で切り替える

### 3. 結果の列がずれている

確認ポイント:

- `Result` シートの同じ行で、右隣の列へ値がずれていないか
- 空欄が多い箇所の前後でずれが出ていないか

よくある原因:

- 元PDF側でセル結合や見た目上の空白が多い
- `Pdf.Tables` が列境界を不安定に認識している

対処:

- 同じ帳票でも列ズレが少ない PDF 群だけに絞って実行する
- まずサンプル件数で確認し、問題なければ大量処理へ広げる
- 必要なら帳票単位で別運用にする

### 4. 同名PDFエラーが出る

症状:

- `同名の PDF は同時に処理できません` と表示される

原因:

- 別フォルダに同じファイル名の PDF が存在する

対処:

- 片方のファイル名を変更してから再実行する
- ファイル名に日付や連番を付ける運用に統一する

### 5. 壊れたPDFで止まる

現行仕様:

- 壊れた PDF が混ざっていても、基本的には `Errors` シートへ退避して処理継続します

確認ポイント:

- `Errors` シートに該当ファイルがあるか
- ログに `Pdf.Tables の読み取りに失敗しました` が出ていないか

対処:

- 壊れた PDF を元システムから再取得する
- その PDF だけ別に開いて正常に表示できるか確認する

### 6. 実行後に Excel が残る

確認ポイント:

- タスクマネージャーで `EXCEL.EXE` が残っていないか
- `output/runtime` に一時 `xlsm` が残っていないか

対処:

- Excel を手動ですべて閉じる
- `output/runtime` が空になるか確認する
- 再現する場合は [test-report.md](../reports/test-report.md) とログをあわせて確認する

### 7. 実行前チェックの内容が想定と違う

症状:

- 対象 PDF 数、保存先、プロファイル名が想定と違う

対処:

- `N` で中止する
- PDF の選び直し、保存先の見直し、`-ProfileName` または `-ProfilePath` の指定見直しを行う
- `VER2` では必要に応じて `[9]` でプロファイルを選び直す

### 8. 環境チェックで `FAIL` が出る

確認ポイント:

- `reports/environment-check.md` の `対処` 列
- `テンプレート再生成導線`
- `実行競合状態`

対処:

- `テンプレート` または `テンプレート再生成導線` が失敗している場合は `scripts/build_excel_template.ps1` を実行する
- `実行競合状態` が `別の実行中` なら、別実行完了後に再実行する
- `実行競合状態` が `前回異常終了の可能性` なら、そのまま再実行して自動回復する
- `実行競合状態` が `内容読取不可` なら、最新ログと `reports/run-history.csv` を確認する
- `Excel COM` が `FAIL` の場合は Excel デスクトップ版の起動可否を先に確認する

### 9. 完了画面に `実行レポートを読み取れませんでした` と出る

確認ポイント:

- 変換自体は成功して `xlsx` が出ているか
- `reports/run-history.csv` に今回実行の行が残っているか
- 最新ログに JSON 読取失敗や書き込み競合が出ていないか

対処:

- 出力 `xlsx` がある場合は内容を確認する
- `reports/run-history.csv` と最新ログで成功/失敗の実態を確認する
- 再現する場合は、ウイルス対策ソフトや同期ソフトが `reports` 配下を監視していないか確認する

## エラー分類の見方

- `PDF読込エラー`
  - PDF 自体が壊れているか、解析できていません。
- `表検出エラー`
  - `Pdf.Tables` が対象表を見つけられていません。
- `列数不一致`
  - プロファイルの `expectedColumns` と帳票の列数が合っていません。
- `システムエラー`
  - スクリプトまたは Excel 実行時の予期しない失敗です。

## ログの見方

補足:

- `VER2 Secure` の正式ログは `%LOCALAPPDATA%\PDF2Excel\logs` に出ます。
- `logs` フォルダでは 30 日超または 200 件超の古いログが自動整理されます。
- 長期保管が必要なログは別の場所へ退避してください。

ログに出やすいメッセージ例:

- `入力 PDF を確認しています。`
  - 入力解決の開始です。
- `Power Query を設定しています。`
  - Excel 側の読込準備です。
- `処理に失敗しました: ...`
  - この行の内容が一次原因です。
- `VBA マクロが使えなかったため、PowerShell 側で xlsx を保存します。`
  - フォールバック動作です。直ちに異常とは限りません。

## 問題報告時に残すとよい情報

- 実施日時
- 実行方法
  - BAT / PowerShell
- 入力PDF数
- 出力先
- `Control` シートの状態
- `Errors` シートの内容
- 最新ログファイル名
- 再現する PDF の特徴
  - 画像PDFか、空欄が多いか、レイアウト差があるか

## 最後の判断基準

- `Errors` が空で `Result` の列ズレもない
  - 実運用に進めて問題ありません。
- `Errors` は少数だが `Result` は安定
  - 壊れた PDF のみ除外して運用可能です。
- `Errors` が多い、または `Result` の列ズレが大きい
  - 帳票グループを分けるか、別仕様の処理を検討してください。
