# PDF2Excel トラブルシューティング

- 作成日: 2026-03-13 00:51 JST
- 作成者: Codex (GPT-5)

## 目的

この資料は、PDF2Excel の実行時に起きやすい問題を、症状別に切り分けるための手引きです。

## まず最初に確認すること

1. [Control シート](C:\Work_Codex\PDF2Excel\docs\user-manual.md) の状態、件数、ログパスを確認する
2. `Errors` シートに何が出ているか確認する
3. `logs` フォルダの最新ログを開く
4. 元PDFがテキスト選択可能か確認する
5. 他の PDF とレイアウト差が大きくないか確認する

## 症状別の対処

### 1. 変換結果の Excel が作成されない

確認ポイント:

- Excel(M365) デスクトップ版が起動できるか
- 保存先フォルダに書き込み権限があるか
- `logs` に `処理に失敗しました` が出ていないか

よくある原因:

- Excel COM 起動失敗
- 保存先の選択ミス
- 出力先ファイルを他のアプリがロックしている

対処:

- Excel を手動で一度起動して閉じる
- 別の保存先を選ぶ
- 同名の `xlsx` を閉じてから再実行する

### 2. `Errors` シートに PDF が多く出る

確認ポイント:

- `ErrorReason` の内容
- `CandidateColumns` と `CandidateRows`

よくある原因:

- レイアウト差が大きい
- 表認識が安定しない PDF
- 30 列を超える表

対処:

- 似た帳票レイアウトごとに分けて実行する
- 実PDFを数件目視確認する
- 30列超の帳票は別処理に切り分ける

### 3. 結果の列がずれている

確認ポイント:

- `Result` シートの同じ行で、右隣の列へ値がずれていないか
- 空欄が多い箇所の前後でずれが出ていないか

よくある原因:

- 元PDF側でセル結合や見た目上の空白が多い
- `Pdf.Tables` が列境界を不安定に認識している

対処:

- 同じ帳票でも列ズレが少ない PDF 群だけに絞って実行する
- まずサンプル件数で確認し、問題なければ大量処理へ広げる
- 必要なら帳票単位で別運用にする

### 4. 同名PDFエラーが出る

症状:

- `同名の PDF は同時に処理できません` と表示される

原因:

- 別フォルダに同じファイル名の PDF が存在する

対処:

- 片方のファイル名を変更してから再実行する
- ファイル名に日付や連番を付ける運用に統一する

### 5. 壊れたPDFで止まる

現行仕様:

- 壊れた PDF が混ざっていても、基本的には `Errors` シートへ退避して処理継続します

確認ポイント:

- `Errors` シートに該当ファイルがあるか
- ログに `Pdf.Tables の読み取りに失敗しました` が出ていないか

対処:

- 壊れた PDF を元システムから再取得する
- その PDF だけ別に開いて正常に表示できるか確認する

### 6. 実行後に Excel が残る

確認ポイント:

- タスクマネージャーで `EXCEL.EXE` が残っていないか
- `output/runtime` に一時 `xlsm` が残っていないか

対処:

- Excel を手動ですべて閉じる
- `output/runtime` が空になるか確認する
- 再現する場合は [test-report.md](C:\Work_Codex\PDF2Excel\reports\test-report.md) とログをあわせて確認する

## ログの見方

ログに出やすいメッセージ例:

- `入力 PDF を確認しています。`
  - 入力解決の開始です。
- `Power Query を設定しています。`
  - Excel 側の読込準備です。
- `処理に失敗しました: ...`
  - この行の内容が一次原因です。
- `VBA マクロが使えなかったため、PowerShell 側で xlsx を保存します。`
  - フォールバック動作です。直ちに異常とは限りません。

## 問題報告時に残すとよい情報

- 実施日時
- 実行方法
  - BAT / PowerShell
- 入力PDF数
- 出力先
- `Control` シートの状態
- `Errors` シートの内容
- 最新ログファイル名
- 再現する PDF の特徴
  - 画像PDFか、空欄が多いか、レイアウト差があるか

## 最後の判断基準

- `Errors` が空で `Result` の列ズレもない
  - 実運用に進めて問題ありません。
- `Errors` は少数だが `Result` は安定
  - 壊れた PDF のみ除外して運用可能です。
- `Errors` が多い、または `Result` の列ズレが大きい
  - 帳票グループを分けるか、別仕様の処理を検討してください。
